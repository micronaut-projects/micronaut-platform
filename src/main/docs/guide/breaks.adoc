This section documents breaking changes between Micronaut versions

== 5.3.0

=== Parent POM

The `exec-maven-plugin` configuration of `micronaut-parent`, which `mvn exec:exec` uses to run the application, no longer passes `-Dcom.sun.management.jmxremote`. The JVM therefore no longer starts the JMX management agent and its local RMI connector before `main`, which shortens the application's startup. The `mn:run` goal and the Gradle `run` task configure their own JVM arguments and are not affected by this change.

JMX keeps working without the flag:

- JConsole, VisualVM and JMC attach to the running JVM through the Attach API, which starts the local agent on demand. `jcmd` does not need the agent.
- Setting `com.sun.management.jmxremote.port` (with its `authenticate` and `ssl` properties) on its own still starts the agent, with both the local and the remote connector.
- A JVM started with `-XX:+DisableAttachMechanism` cannot start the agent on demand, so local tools need the flag there.

To pass the flag again for one run, replace the arguments with `exec.args`. The single quotes keep the shell from expanding `${exec.mainClass}`, so that Maven resolves it:

[source,bash]
----
./mvnw exec:exec -Dexec.args='-classpath %classpath -XX:TieredStopAtLevel=1 -Dcom.sun.management.jmxremote ${exec.mainClass}'
----

To pass it on every run, override the arguments in the application's POM:

[source,xml]
----
<plugin>
    <groupId>org.codehaus.mojo</groupId>
    <artifactId>exec-maven-plugin</artifactId>
    <configuration>
        <arguments combine.self="override">
            <argument>-classpath</argument>
            <classpath/>
            <argument>-XX:TieredStopAtLevel=1</argument>
            <argument>-Dcom.sun.management.jmxremote</argument>
            <argument>${exec.mainClass}</argument>
        </arguments>
    </configuration>
</plugin>
----

== 5.0.0

=== Removals

- `micronaut-microstream` has been removed from the Micronaut platform.
- `micronaut-rxjava2` has been removed from the Micronaut platform.

See <<platform-5-migration-impact,Platform 5 Migration Impact>> for the generated appendix of accepted Platform 5 BOM and version-catalog regressions.

=== Build Tool Support

Starting with Micronaut Platform 5.0, Kotlin applications built with Maven are not supported. This support-policy change is limited to the Kotlin and Maven combination: Java applications built with Maven remain supported, and Kotlin applications built with Gradle remain supported.

Kotlin Micronaut applications should move to Gradle when upgrading to Micronaut Platform 5.0 or later. Applications that require Maven with Kotlin should remain on a supported Micronaut 4.x release line until they can migrate their build.
